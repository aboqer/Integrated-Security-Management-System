# قاعدة بيانات نظام الإدارة الأمنية للمنفذ البري

هذه الملفات تضع الأساس الحقيقي لقاعدة بيانات PostgreSQL التي ستخدم الواجهات الحالية والأنظمة الخمسة:

- نظام المخالفات
- نظام الأمانات
- نظام البلاغات والشكاوي
- نظام الموقوفين
- نظام الالتزامات

## الملفات

- `schema.sql`: إنشاء الجداول والأنواع والعلاقات والفهارس.
- `seed.sql`: بيانات تأسيسية للإدارات، الأدوار، الصلاحيات، المواقع، وأنواع السجلات.

## طريقة التشغيل

```powershell
psql -U postgres -d security_management -f database/schema.sql
psql -U postgres -d security_management -f database/seed.sql
```

أو بعد إنشاء قاعدة جديدة:

```sql
CREATE DATABASE security_management;
```

## الفكرة العامة

تم فصل البيانات المشتركة عن بيانات الأنظمة حتى لا تتكرر معلومات الشخص أو المركبة في كل شاشة:

- `people`: الأشخاص.
- `person_identities`: الهويات والجوازات والبطاقات.
- `person_phones`: أرقام التواصل.
- `vehicles`: المركبات واللوحات.
- `locations`: مواقع المنفذ.
- `departments`: الإدارات الخمس وإدارة النظام.
- `users`, `roles`, `permissions`: المستخدمون والصلاحيات.

## ربط الأنظمة

### المخالفات

الجداول الرئيسية:

- `violation_types`
- `violations`

يدعم النظام الشخص، المركبة، الموقع، الإدارة، الحالة، الأولوية، المرفقات، وسجل العمليات.

### الأمانات

الجداول الرئيسية:

- `custody_records`
- `custody_items`
- `custody_deliveries`

يدعم استلام الأمانات، حفظ عدة عناصر تحت تذكرة واحدة، ثم تسليمها وتوثيق المستلم والمفوض.

### البلاغات والشكاوي

الجداول الرئيسية:

- `report_categories`
- `reports_complaints`

يدعم بلاغ أو شكوى، مصدر البلاغ، المبلغ، الشخص المرتبط، الإدارة المختصة، الأولوية، الإغلاق، وملخص المعالجة.

### الموقوفين

الجداول الرئيسية:

- `detainee_cases`
- `detainee_events`

صمم هذا النظام كدورة حياة كاملة، وليس نموذج إدخال فقط. ملف الموقوف يمكن أن يرتبط بمخالفة أو بلاغ، ويسجل كل إجراء في `detainee_events` مثل التحويل، التحقيق، الإفراج، أو تحديث الحالة.

### الالتزامات

الجداول الرئيسية:

- `commitment_types`
- `commitments`

هذا هو سجل الالتزامات والتعهدات. يمكن ربط الالتزام بشخص فقط، أو بمخالفة، أو بلاغ، أو ملف موقوف. هذا سيسهل التقارير والرجوع التاريخي.

## الجداول المشتركة

- `attachments`: مرفقات عامة لأي نظام.
- `status_history`: تاريخ تغيير الحالات لأي سجل.
- `audit_logs`: سجل عمليات شامل لكل الأنظمة.

## ملاحظات مهمة للمرحلة القادمة

1. الواجهة الحالية تستخدم `localStorage`; الخطوة التالية هي بناء Backend يستبدل ذلك بـ API.
2. يفضل إنشاء طبقة خدمات في الواجهة مثل `src/services/violations.ts`.
3. يفضل اختيار ORM مثل Prisma أو Drizzle قبل بناء API حتى تصبح الهجرات منظمة.
4. لا تخزن الملفات داخل قاعدة البيانات؛ استخدم `attachments.storage_key` للإشارة لمسار الملف في التخزين.
